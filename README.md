# 五子棋小程序 - 第三阶段（联机对战）

在第二阶段基础上新增好友房间、随机匹配、实时棋局页面及 Node.js WebSocket 服务端。原有首页、个人中心和单机摆谱保留。

## 目录
- `config.js`：联机服务器与 HTTPS API 地址配置（区分开发版/体验版与正式版）
- `pages/room`：创建 6 位房间号、加入好友房间
- `pages/matching`：随机匹配及取消匹配
- `pages/game`：15×15 在线棋盘、轮流落子、胜负状态
- `utils/socket.js`：小程序 WebSocket 连接封装，含 25 秒应用层心跳
- `utils/player.js`：游客/本地用户身份
- `server/server.js`：服务端权威棋局、房间和匹配队列，含心跳清理与空闲房间回收
- `server/smoke-test.js`：服务端协议冒烟测试

## 本地启动服务端
需要 Node.js 18 或更高版本：

```bash
cd server
npm install
npm start
```

服务默认监听 `3000` 端口；访问 `http://localhost:3000/health` 可检查服务状态。服务端附带冒烟测试，需先启动服务，再执行：

```bash
npm test
```

## 小程序连接配置
地址集中在 `config.js`：

- `DEV_WS_BASE_URL`：开发版/体验版使用，默认 `ws://127.0.0.1:3000`（开发者工具本机联调）；真机联调改成电脑局域网 IP，例如 `ws://192.168.1.10:3000`。
- `PROD_WS_BASE_URL`：正式版使用，必须是 `wss://` 合法域名；留空时正式版会提示“尚未配置联机服务器”，不会误连测试服。
- `API_BASE_URL`：微信登录换取 Token 的 HTTPS 接口，留空时保持游客模式。

`app.js` 启动时按 `envVersion` 自动选择：正式版用 `PROD_WS_BASE_URL`，其余环境用 `DEV_WS_BASE_URL`。

不要在正式小程序中使用 `ws://` 公网明文连接。部署时应配置 HTTPS/WSS 证书，并在微信公众平台「开发管理-开发设置-服务器域名」中添加合法 socket 域名。开发者工具本地联调可按实际情况临时调整“不校验合法域名”等选项，但上线前必须恢复并配置正式域名。

## 联调步骤
1. 先启动服务端，并确保小程序设备能访问该服务。
2. 修改 `config.js` 的 `DEV_WS_BASE_URL`。
3. 使用两个不同微信开发者工具实例/两台设备测试好友房间：设备 A 创建房间并复制房间号，设备 B 输入房间号加入。
4. 两端进入棋局后交替落子，验证双方棋盘同步及五子连线结束。
5. 再分别从两端测试随机匹配、取消匹配和断线重连。

## 当前阶段边界与上线前必做
- 当前服务端使用内存保存房间和匹配队列；进程重启会清空对局，不适合多实例部署。正式环境应增加 Redis/数据库及房间状态持久化。
- 当前 playerId 是客户端生成的游客标识，服务端尚未验证微信登录 Token。它仅用于开发联调，不能作为正式身份认证或防作弊机制。上线前需把第二阶段微信登录接入服务端，校验 Token 并由服务端确定玩家身份。
- 当前支持房间内实时落子、服务端回合校验、落子位置校验、胜负判断、基础断线重连、应用层心跳，以及弃房/空闲房间与匹配队列回收；暂未实现认输、和棋协商、观战、聊天、超时判负及完整对局记录。
- 正式部署需要进程守护、日志、限流、反作弊和安全审计。

## 说明
本阶段提供可运行的基础联机闭环，需部署服务端并配置合法 WSS 域名后才能进行跨设备联机测试。JavaScript 与 JSON 配置可做静态语法检查，但最终仍需在微信开发者工具和真实网络环境中验证。
